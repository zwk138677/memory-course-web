# 物理选项公式字体一致性修复

## 问题

知识正文中的无空格表达式 `u>2f`、`f<u<2f` 已能整体交给 KaTeX 渲染，但相同内容在知识填空选词库和快速练习中仍可能混用数学字体与正文字体。

真实《凸透镜的应用》成品 DOCX 暴露了两种遗漏：

- 独立选项 `2f` 没有被识别为公式，仍以普通文本显示。
- 带空格的链式不等式 `f < v < 2f` 只被识别为 `$f<v$` 加普通文本 `< 2f`。

两处组件都调用 `rendering.py` 中的共享纯文本公式标准化函数，因此根因位于共享识别规则，而不是 KaTeX 字体资源或组件 CSS。

## 方案

扩展共享纯文本公式识别器：

- 将紧邻的“数字系数 + 单个小写变量”识别为完整公式，例如 `2f`、`3x`。
- 允许链式表达式的相邻比较项之间存在空格，使 `f < v < 2f` 整体标准化为 `$f<v<2f$`。
- 继续由知识正文、知识填空选词库和快速练习共用同一套标准化逻辑，不在各组件内增加重复规则。
- 只改变展示 HTML。选项的原始文本、`data-text`、正确答案和提交判分值保持不变。
- 保持已有 LaTeX 分隔符、普通英文、分数和物理单位保护规则；`dB`、`DB`、`db` 等大小写敏感答案不得被改写。

## 验收标准

- `2f` 显示为一个完整 KaTeX 数学节点。
- `f < v < 2f` 显示为一个完整 KaTeX 数学节点，不再留下普通字体的尾部 `2f`。
- 知识填空选词库与快速练习使用相同显示结果。
- 原始答案文本保持 `2f` 或 `f < v < 2f`，答题提交与判分不受影响。
- 现有 `u>2f`、`f<u<2f`、物理单位和大小写敏感选项测试继续通过。

## 验证

先添加失败测试，分别覆盖共享标准化函数、选词库 HTML 和快速练习 HTML，再实施最小正则修复。随后运行完整测试套件与 Python 编译检查，并使用真实《凸透镜的应用》DOCX 做解析和浏览器渲染冒烟验证。
